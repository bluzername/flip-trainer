# Flip Trainer

[![CI](https://github.com/bluzername/flip-trainer/actions/workflows/ci.yml/badge.svg)](https://github.com/bluzername/flip-trainer/actions/workflows/ci.yml)

A two-device, local-only workout system.

- **Galaxy Z Flip5** - a dedicated edge-vision appliance. Captures video, runs pose inference,
  decides exercise phase and repetitions, evaluates a small number of high-confidence movement
  rules, and writes a durable append-only local event log. It owns the real-time loop.
- **iPhone** - the user-facing app. Chooses the exercise, configures and controls the set, shows
  live progress, accepts weight/rep corrections, and stores workout history locally.
- **BLE** carries commands, status, and compact workout events between them. Nothing else does.

No internet, no accounts, no cloud. Raw video never leaves the Galaxy.

Full plan: [`docs/IMPLEMENTATION_PLAN.md`](docs/IMPLEMENTATION_PLAN.md).
Agent rules: [`AGENTS.md`](AGENTS.md). Current state: [`docs/STATUS.md`](docs/STATUS.md).

## Layout

```
android-sensor/core/     pure JVM - geometry, readiness, evaluators, session lifecycle
android-sensor/app/      Android shell - CameraX, MediaPipe, Room, BLE GATT, Compose
protocol/                .proto wire format, pairing crypto, envelopes, ack/replay engine
ios-app/                 Swift / SwiftUI companion (XcodeGen project.yml, generated .xcodeproj)
exercise-definitions/    versioned JSON: thresholds, required landmarks, metadata
test-fixtures/           golden expected events (committed) + pose traces (synthetic ones are
                         regenerated by the tests; recorded ones are committed when they exist)
tools/trace-inspector/   offline CLI: replay a trace through an evaluator
scripts/doctor.sh        environment check: what is installed, what is missing, what to run next
docs/                    plan, status, decisions, device notes, test matrix, physical protocols
.github/                 CI workflow and Dependabot config
```

The important structural rule: **all decision logic is pure JVM and unit-tested without a
device.** `android-sensor/app` is a thin shell. See ADR-0001 in `docs/DECISIONS.md`.

## Build and test

The JVM modules need only a JDK 17+ - no Android SDK, no emulator, no device:

```bash
./gradlew verify              # compile + ktlint + all unit tests (274 today)
./gradlew :android-sensor:core:test
./gradlew :protocol:test
./gradlew ktlintFormat        # before committing; the checks are strict
```

`verify` is a root task (see `build.gradle.kts`) that depends on `check` for every module that
applies the Kotlin JVM plugin, so it runs whatever can be built in the current environment.
CI runs the same command on every push and pull request (`.github/workflows/ci.yml`).

`settings.gradle.kts` includes `:android-sensor:app` **only** when an Android SDK is configured
via `ANDROID_HOME`, `ANDROID_SDK_ROOT`, or `sdk.dir` in `local.properties`. Without one, the
build cleanly excludes it and everything else still builds and tests.

Replay a trace through an evaluator without a phone. Synthetic traces appear under
`test-fixtures/pose-traces/` after the test suite has run once (they are gitignored and
regenerated deterministically; see `test-fixtures/README.md`):

```bash
./gradlew :tools:trace-inspector:installDist
./tools/trace-inspector/build/install/trace-inspector/bin/trace-inspector --list
./tools/trace-inspector/build/install/trace-inspector/bin/trace-inspector \
  --trace test-fixtures/pose-traces/curl_synthetic_10reps_clean.jsonl
./tools/trace-inspector/build/install/trace-inspector/bin/trace-inspector \
  --trace <file> --format events   # golden-file form
```

The Gradle `run` task works too, but its working directory is the module, so paths are relative
to `tools/trace-inspector/`:

```bash
./gradlew :tools:trace-inspector:run --args="--trace ../../test-fixtures/pose-traces/curl_synthetic_10reps_clean.jsonl"
```

## Android

Requires the Android SDK (`compileSdk` 37, see `android-sensor/app/build.gradle.kts`) and a Flip5
in developer mode.

> **This module has never been compiled.** It was written without an Android SDK, and every
> Android-side dependency version in `gradle/libs.versions.toml` is unverified until it has
> (ADR-0009). CI runs `assembleDebug` as a non-blocking job so the first compile happens somewhere
> reproducible; expect it to fail until someone fixes the module on a real SDK.

```bash
export ANDROID_HOME=$HOME/Android/Sdk
./gradlew :android-sensor:app:assembleDebug
./gradlew :android-sensor:app:installDebug
adb shell am start -n com.fliptrainer.sensor/.MainActivity
adb logcat -s FlipTrainer:V
```

The main-screen digitizer on the target Flip5 is dead, so the appliance is driven without touch:

```bash
scrcpy                                                    # mouse/keyboard over USB
adb shell am start -a com.fliptrainer.action.SHOW_PAIRING # force pairing QR
adb shell am broadcast -a com.fliptrainer.action.UNPAIR   # recovery: forget the controller
```

## iOS

Requires Xcode 16+, `xcodegen`, and a device that can run locally signed builds. The
`.xcodeproj` is generated from `ios-app/project.yml` and is not committed (ADR-0006).

> **This app has never been compiled either.** See `ios-app/README.md` and `docs/STATUS.md`.

```bash
brew install xcodegen
cd ios-app
xcodegen generate
open FlipTrainer.xcodeproj
xcodebuild -project FlipTrainer.xcodeproj -scheme FlipTrainer \
  -destination 'platform=iOS Simulator,name=iPhone 16' test
```

## Not in scope

Dual-camera capture, stereo depth, automatic exercise recognition, visual weight recognition,
multi-person, Apple Watch, cloud/login/sync, social features, injury prediction, medical claims,
root, custom ROM, Knox modification. See section 12 of the implementation plan and the revisit
triggers in section 13 before proposing any of them.
