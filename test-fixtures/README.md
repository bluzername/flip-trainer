# test-fixtures

Two kinds of file, with deliberately different rules.

## `pose-traces/` — inputs

Versioned JSONL landmark traces (ADR-0004). Never video, never pixels — coordinates,
confidence and time. That is what makes them safe to commit and safe to attach to a bug report.

| Kind | Header `deviceId` | Committed? | Why |
| --- | --- | --- | --- |
| **Synthetic** | `synthetic` | **No** | Deterministically regenerated by the test suite from `SyntheticPose` + `SyntheticMotion`. Committing megabytes that a function can reproduce exactly buys nothing. |
| **Recorded** | the real device id | **Yes** | Irreplaceable. A recording of a person doing reps cannot be regenerated, and it is the only input that can support an accuracy claim. |

Synthetic traces are gitignored by the `*_synthetic_*.jsonl` pattern. Run the tests once and they
appear locally.

**A synthetic trace can never satisfy a validation gate.** It proves the evaluator is
deterministic and that thresholds behave as written. It says nothing about whether the thresholds
are right for a human being. Plan §11.3: ground truth comes from a person, not from a generator.

## `expected-events/` — goldens

The event stream each trace must produce, byte for byte. **Always committed.** When a threshold
changes, the diff on these files *is* the review — that is the whole point.

Regenerate deliberately:

```bash
./gradlew :android-sensor:core:test -Dfliptrainer.updateGoldens=true
git diff test-fixtures/expected-events   # read this before committing it
```

A golden that is regenerated without reading the diff is worse than no golden, because it
converts a caught regression into a recorded one.

## Recording a real trace

1. Enable the trace recorder in the Android debug screen (opt-in, off by default).
2. Perform the set while a human counts out loud and writes down the true count.
3. Pull the trace: `adb pull /sdcard/Android/data/com.fliptrainer.sensor/files/traces/<file>`.
4. Fill in `humanRepCount` and `notes` in the header. A trace without human ground truth is an
   input, not evidence.
5. Commit it here and add the corresponding row to `docs/TEST_MATRIX.md`.
